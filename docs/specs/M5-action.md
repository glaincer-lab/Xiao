## 1. 目的与范围

从"控电脑"扩展到"控环境+给方案"：Home Assistant 主路径接入、米家直连实验性、VLM 坐标兜底操电脑、行程/饮食建议编排。

**明确不做**：自建设备协议（一切经 HA/官方生态）；主动类执行设备操作（白名单外一律转建议）；无验证的执行。

## 2. 前置依赖

- M0：授权中心（动作三级分级）、进程黑名单（工具分发层拒授权）、**跨模块事件总线 `backend/event_bus.py`（已实现）**
- M1：惯例画像（偏离惯例确认）、记忆（偏好上下文注入建议）
- 现有底座：语音操电脑六工具（UIA+审批 fail-closed）、多模态贴图

**外部生态（含风险分级）**：

| 层 | 路径 | 定性 |
|---|---|---|
| 层 0 | 建议+手动（默认） | 只说不动：温度/窗帘/色温等实体设备用户操作；可自动仅限通知弹窗+传感器查询 |
| 层 1 | Home Assistant（**唯一推荐**） | REST/WebSocket+长期访问令牌；秒级推送支持读回验证；米家经 hass-xiaomi-miot |
| 层 2 | MiService 米家直连（**实验性，默认关**） | 首次启用弹窗（文案 **config 可配**，`m5.miservice_warning`，非硬编码——固件更新频率高于产品发版）："该方式非小米官方接口，基于社区逆向方案，可能随小米固件更新失效。开启后将持续尝试重连，如遇异常可随时关闭。" |

华为：小二给华为智家当大脑（非求接入）；第三方本地控制 API 未公开前不承诺；过渡期 Matter 通道经层 1。

```yaml
device_command:
  intent: "调暗客厅灯"
  target: {ha_entity: "light.living_room"}      # 层1 / {miot_did} 层2
  pre_state: {...}                               # 执行前读回
  post_state: {...}                              # 读回验证结果
  approval_level: suggest|confirm|whitelist_auto
home_routine_profile:            # 惯例画像（M1.7 喂入）
  typical_params: {客厅灯色温: 4000K, ...}
  rebuilding: false              # 过渡期重建模式

  constraints: {时间, 人数, 预算}
  options: [≤3, 各带代价+置信度]
  landed: {calendar_event_id}    # 落地凭证（写日历/设提醒）
```

## 4. 状态机 / 流程（E 型硬标准）

```
语音指令 → 意图解析 → 查设备状态（感知先于行动）→ 判定
  → [偏离惯例确认："这比平时早了1小时，确认不是手滑？"]（仅偏离时）
  → [审批分级：建议/确认/白名单自动]
  → 执行 → 读回验证 → 播报结果
失败路径：设备离线→人话报错+下一步建议；读回不一致→"好像没成功，你再看看？"只播报一次
```

**读回验证分档（写死）**：层 1=5 秒读回；层 2=执行确认+15-30 秒延迟复查（轮询延迟所限）。

**场景编排**："我要看电影了"=灯+窗帘+电视多动作序列 → 经 HA scene（一次调用），非逐设备。

**VLM 坐标兜底操电脑**：UIA 失败→截屏→VLM 定位→**展示确认**→执行→**前后截屏 diff 验证**（Operator 38 分教训：执行≠成功）；坐标缩放映射（低分辨率推理→实际分辨率换算）；支付页/密码框硬黑名单；进程黑名单（M0.3）前台时工具层直接拒授权。

**行程/饮食编排（A 型范式）**：澄清（去哪/几点/谁）→查工具（天气/地图/日历，外部失败降级给部分建议并明说缺什么）→≤3 方案各带代价+置信度→敢给推荐→**落地动作必须明确**（写日历/设提醒，建议不落地=白搭）→事后复盘（"那家餐厅怎么样"）入画像。

## 5. 规则与话术

- 感知先于行动："有点冷"→先查温度传感器，无数据先问，有数据才建议/调温
- 过渡期重建模式（M1.7 联动）：搬家后惯例失效，偏离确认变多时明说原因（"我在重新记你的新习惯"）
- 层 2 状态异常不重试轰炸：失败 3 次即停+提示转层 1 或手动

## 6. 模块间接口（事件总线契约表）

| 事件名 | payload | 发布者 | 订阅者 | 备注 |
|---|---|---|---|---|
| `device.command` | `{target,action,approval_level}` | M5 | 执行器 | 经授权中心分级 |
| `device.state_changed` | `{entity,前后态}` | M5/M0.3 | M1（惯例画像）/M3 | HA 推送驱动 |
| `env.anomaly` | `{传感器,数值}` | HA 推送 | M3/M2 | 紧急穿透白名单判定 |
| `plan.landed` | `{方案,落地凭证}` | M5 | M1/M6 | 复盘与成长记录素材 |

## 7. 验收断言

- 模块级：执行前必有 pre_state 断言；执行后必有读回断言（层 1=5s/层 2=延迟复查）；白名单外主动执行=0 断言；进程黑名单拒授权断言；VLM 兜底前后 diff 验证断言；支付/密码页黑名单断言；层 2 默认关闭+弹窗文案断言
- EVAL 关联：偏离惯例确认、危险操作审批（现有场景延伸）

## 8. 开放问题

1. HA 的 conversation agent 注册（让全屋音箱入口都由小二当大脑）——HA 自定义对话代理机制可行性待原型验证。
2. 米家直连的账号安全（token 存储加密方案）。
3. 多设备并发指令的编排顺序（"看电影"三动作的执行序）。
