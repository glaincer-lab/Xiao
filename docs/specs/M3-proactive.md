## 1. 目的与范围

让小二"先开口且开口有料"：时间心跳+事件触发+回归简报，全部收口于总闸门与预算制。

**明确不做**：屏幕持续监控；无记忆支撑的寒暄（"在吗"式心跳）；MVP 期间整个引擎不上线（总闸门 UI 先行）。

## 2. 前置依赖

- M1：记忆检索（心跳内容生成、纪念日、哀伤节奏）
- M2：当前姿态与情感状态（不开口于陪伴态进行中）
- M0：宏观四态（DORMANT 冻结）、注意力传感器（全屏/空闲）、授权中心（总闸门）
- 现有底座：tasks.py（调度）、通知管道（任务完成通知已有）

## 4. 状态机 / 流程

### 4.1 候选消费流程（预算制）

```
候选生成（心跳定时/事件触发/回归简报/纪念日）
  → 四维打分排名
  → [关系价值单项爆表（生日/纪念日）？→ 豁免穿透，不占额度]
  → 总分 >0.6 → 消费 1 条额度 → 勿扰检查（时段/冷却/注意力）→ 开口
  → 总分 ≤0.6 → 静默丢弃（记日志供调参）
```

**全屏冻结**：全屏期候选**丢弃不攒**（防集中轰炸）；游戏后允许一条轻评（"刚才那局怎么样"）。

### 4.2 心跳

定时（早/晚/时段）→ 查记忆+日程 → 生成候选 → **内容质量门**（无素材宁可不说；生成后自评分）→ 消费预算 → 开口。无响应退避：标记已说不追问；连续 N 天无响应自动降频；回应率进 style_profile 反向调节。

### 4.3 事件触发

事件源（日程临近/天气突变/任务完成/HA 传感器/纪念日/哀伤节点）→ 相关性判定 → 紧急度分级 → 通知策略（立即/攒着/只亮灯）→ 同类窗口聚合（防事件风暴）→ 冷却检查。

**预判型触发**（三源 join）：天气降温+明日日程+历史偏好 → 明早加衣提醒。

### 4.4 DORMANT 联动（M0 硬约束）

DORMANT：本引擎**冻结非降频**，零消息零归因；托付任务照常办不推送，进展进 RETURNING 简报。

### 4.5 数字纪念日（v4 终裁）

**彻底废除纯计数型**（第 N 句话）。保留穿透豁免两类（月 ≤1-2，同乐态）：
1. 里程碑能力见证（与 M6.1 双源入册联动）："这是我第一次不问你就把房间调到 25 度，记进咱们的本子里吧？"
2. **正向极值见证**（恢复/坚持/成就 only）："你连续三周周末都休息了，这半年头一次——今天打算去哪转转？"

**画像异常侦测纪律**：负向异常（打破惯例）**永不主动开场**——仅①响应时 Context 增强 ②偏离惯例确认。监控感是家人感死穴。

## 5. 规则与话术

- 硬护栏：勿扰时段+全局冷却+每日额度上限；紧急穿透例外（什么算紧急用户可配）
- 主动类只建议不执行（物理操作白名单外一律转建议）；主动+物理执行权限强制隔离
- 主动风格画像：只学行为（回应率/回应速度/信息密度偏好），不推断依恋类型不存心理标签；手动设置覆盖自动学习
- 复访通道（M2.2 冲突复访）走关系价值通道零计费；被新干预压制时静默过期

## 7. 验收断言

- EVAL.md 二批：DORMANT 冻结零消息断言；RETURNING 分层模板匹配
- 模块级：日额度硬上限断言（任何路径消费不得超 quota）；全屏期零投递断言；无响应 3 天降频断言；哀伤节奏 3/7/30 天触发断言；紧急穿透仅限用户配置清单

## 8. 开放问题

1. 预算默认值（3 条/天）与 >0.6 阈值全靠灰度调——影子期先跑"假投递"（只记录会投什么），并**同步收集用户实际响应率**，否则上线后无法判断额度是否合适（v4.1.1）。
2. 心跳的时段分布（早/午/晚各几次）需按用户作息画像个性化，首版固定三档。
3. 跨事件预判推理的触发精度未知，先只在天气+日程两源上线。
